# "Rings, Not Edges" — LaTeX project (draft v3, audit framing)

## Compile

Overleaf: upload `RingShield-paper-latex.zip` as a new project; `main.tex` is at the top
level. Compiler: pdfLaTeX.

Locally:

```
pdflatex main
bibtex main
pdflatex main
pdflatex main
```

No LaTeX compiler was available on the machine that produced this draft, so it has **not**
been compiled. A static check passes (environments balanced, every `\input` and figure path
exists, every `\ref` and `\cite` key resolves); expect at most float-placement and overfull-box
warnings.

## Layout

- `main.tex` — article class; `\input`s one file per section, in this order: abstract,
  introduction, related, data (evaluation protocol), findings (benchmark audit), method
  (reference pipeline), results (results + where recovery stops), recommendations,
  limitations, conclusion, appendix.
- `tables/` — every table as its own booktabs file, built from `results/tables/` in the
  repository.
- `figures/` — four figures built for the paper (`fig_*.png`, generated by
  `../make_figs.py` from repository tables), three repository figures and two dashboard
  screenshots. The pipeline diagram is TikZ inside `sections/method.tex`.
- `references.bib` — works the repository references plus the related work added on
  2026-11-13 from a literature search; three entries still have incomplete author lists.

## Packages (all standard on Overleaf)

geometry, graphicx, booktabs, amsmath, siunitx, tikz (positioning, arrows.meta), xcolor,
caption, subcaption, natbib, hyperref.

## Conventions

- `\ci{x}{lo}{hi}` renders a point estimate with its 95 % bootstrap CI.
- Every number carries a `% source: <path> (<row/column>)` comment naming the repository file
  it comes from. See `../CLAIMS_CHECK.md` for the audit and `../OPEN_QUESTIONS.md` for open
  decisions.
- Headline numbers are the primary window (test days 8–9).
- Internal experiment codes appear only in `% source` comments, never in the prose.
