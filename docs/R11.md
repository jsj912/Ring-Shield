# R11: gated retraining with simulated verdicts (amends spec v1.1, Section 8.2)

**What R11 is.** A demonstration that the feedback loop works end to end: simulated verdicts are
recorded, they feed one real retrain of the ring layer, the frozen-holdout gate decides, and the
outcome serves the rest of the window. **It is not an effectiveness experiment.** It cannot measure
whether feedback improves accuracy: one bank produces about 5 rings in 48 h, and its verdicts are
about 0.06 % of the expansion policy's training rows. No improvement is claimed from it.

Every verdict is simulated (`is_simulated = TRUE`) from ground truth, at accuracy a = 0.90 and
a = 0.70, and every table says so.

## Amendments to spec v1.1 (decided 2026-10-24, before the run)

| # | v1.1 said | R11 does | why |
|---|---|---|---|
| 1 | 12 four-hour cycles over the primary window | the same, and **only** days 8–9: the old 10-cycle loop over days 8–17 is removed | days 0–7 are train and validation and must never be replayed; days 10–17 are the degenerate tail |
| 2 | the tenant's rings | rings built by `platform/jobs/build_tenant_rings.py` (`--edge-subset`, fixed pooled cutoff) from the bank's own scores, `scored_edges_visible_{T}_{model}_{seed}.parquet` from the 22 Oct hand-off | the bank's own view, as in R10's primary row |
| 3 | review fraction ρ = 0.05, highest confidence first | **ρ = 1.0**: every open ring of the tenant in each cycle. The simulator's queries and verdict rules are unchanged | at 5 % a single bank yields almost no verdicts |
| 4 | retrain every cycle | **exactly once, after cycle 6** (end of day 8), `ringshield train` for expansion and affinity, with the holdout guard and no minimum label count. If the gate accepts, the new model serves cycles 7–12; if it refuses, the old model carries on | one retrain on a day's verdicts is what the data supports |
| 5 | refit expansion, affinity and typing | **typing is not refit**; the R5 head stays fixed | `ringshield train` retrains expansion and affinity only |
| 6 | acceptance: the gate refuses at least one model in a logged run | the refusal is **shown by a unit test**, not forced in the run: flipped verdicts make the candidate worse on the holdout and the gate refuses it (`platform/tests/test_retrain_job.py::test_gate_rejects_a_retrain_made_worse_by_flipped_verdicts`) | forcing a refusal in the run would be staging a result |
| 7 | a dedicated tenant | **bank 1**: of the primary tenants 1, 20, 11, 118, 12, the one with the most seed-1 tenant rings in days 8–9 (ties: more visible test edges) | see the table below |

## Result (2026-10-24, bank 1)

All verdicts simulated. Holdout ring-F1 on the frozen validation holdout; gate ε = 0.005.

| accuracy | verdicts day 8 / day 9 | base model (= no-retrain control) | retrained expansion | retrained affinity | serving cycles 7–12 |
|---|---|---:|---:|---:|---|
| 0.90 | 6 / 1 | 0.6883 | 0.6612, refused | 0.6556, refused | base model |
| 0.70 | 6 / 1 | 0.6883 | 0.6531, refused | 0.6639, refused | base model |

The loop runs end to end: verdicts are recorded, one real LightGBM retrain uses them, the candidate is
scored on the frozen holdout and the gate refuses it, so the old model carries on. The 0.90 numbers
reproduced exactly on a second run. **No claim about the effect of feedback follows**: six verdicts
cannot move a policy trained on the full training set, and the refusals are what that predicts.
Per-cycle tables: `results/platform/r11/accuracy_0.90/cycles.md`, `accuracy_0.70/cycles.md`.

### Platform defects found and fixed by running R11

| defect | effect | fix |
|---|---|---|
| `record_verdict` set the ring status to the verdict verb (`confirm` / `reject`) | every confirm or reject failed `ck_rings_status` on a real database, including the dashboard's buttons | map to `confirmed` / `rejected`; test that every verdict maps to an allowed status |
| the first retrain stamped the base model's baseline row with the current time | every verdict made before a tenant's first retrain counted as old, so it never learned from feedback | stamp it with the base model's write time (`base_trained_at`) |
| the adapter called `ringshield train` without the labels' context | the real trainer refuses non-empty labels without `--scores` / `--rings` | `l6.retrain.label_scores_template` / `label_rings_template`, passed with GFP and embeddings |
| the platform read `training_labels.rings` as plain strings | the real trainer writes records (`{"ring_id": ...}`), so every retrain failed | accept both forms |
| `run-demo.ps1` required exactly 5 rings for every bank | any bank other than 12 / 20 could not be loaded | apply the count only to the documented 12 / 20 demo files |

## Run

```powershell
cd platform
python -m experiments.r11_gated_retrain --tenant-id 1 --accuracy 0.90
python -m experiments.r11_gated_retrain --tenant-id 1 --accuracy 0.70
```

Restore the tenant's baseline (reload the demo database) between the two accuracy conditions: the
run writes simulated verdicts and model history. Outputs: `results/platform/r11/accuracy_<a>/`
(`cycles.md`, `run.json` with config and input hashes). The no-retrain control is the base model's
holdout ring-F1, held fixed across all 12 cycles.
